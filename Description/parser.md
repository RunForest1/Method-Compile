## 2. КС-грамматика языка, в которой лексемы суть терминалы
Синтаксический анализатор оперирует не отдельными символами исходного кода, а **лексемами**, выданными конечным автоматом (раздел 1). Множество терминалов грамматики совпадает с алфавитом выходных кодов лексера.

### 2.1. Алфавит терминалов (лексема)
| Лексема (в коде) | Описание | Пример |
|:---|:---|:---|
| `L_ID` | Идентификатор переменной/массива | `a`, `matrix`, `temp1` |
| `L_NUM` | Числовая константа (int/float) | `42`, `3.14` |
| `L_ADD` | Операции низшего приоритета | `+`, `-` |
| `L_MUL` | Операции высшего приоритета | `*`, `/` |
| `L_ASSIGN` | Оператор присваивания | `:=` |
| `L_READ` | Оператор ввода | `read` |
| `L_WRITE` | Оператор вывода | `write` |
| `L_IF`, `L_THEN`, `L_ELSE` | Ветвление | `if`, `then`, `else` |
| `L_WHILE`, `L_DO` | Цикл | `while`, `do` |
| `L_CMP` | Операции сравнения | `<`, `>`, `<=`, `>=`, `==`, `!=` |
| `L_DELIM` | Скобки и разделители | `(`, `)`, `[`, `]`, `;`, `,` |
| `L_EOF` | Маркер конца входной цепочки | `⊥` |

### 2.2. Правила порождения (БНФ)
Стартовый символ: `Program`. Грамматика описывает структуру операторов, выражений и управляющих конструкций.
```
Program     → StmtList L_EOF
StmtList    → Stmt ; StmtList | λ
Stmt        → L_ID L_ASSIGN Expr
            | L_READ L_ID
            | L_WRITE Expr
            | L_IF Cond L_THEN StmtList L_ELSE StmtList
            | L_WHILE Cond L_DO StmtList
Cond        → Expr L_CMP Expr
Expr        → Expr L_ADD Term | Expr L_SUB Term | Term
Term        → Term L_MUL Factor | Term L_DIV Factor | Factor
Factor      → ( Expr ) | L_ID ArrayIdx | L_NUM
ArrayIdx    → [ Expr ] | λ
```
*Примечание:* Вертикальная черта `|` разделяет альтернативы. `λ` обозначает пустую цепочку.

## 3. КС-грамматика языка, преобразованная в нестрогую нормальную форму Грейбах
Для обеспечения детерминированного LL(1)-анализа исходная грамматика преобразуется по алгоритму.

### 3.1. Устранение левой рекурсии
Правила для `Expr` и `Term` содержат непосредственную левую рекурсию. Заменяем их по шаблону `A → Aα | β` → `A → βA'`, `A' → αA' | λ`:
```
Expr  → Term U
U     → L_ADD Term U | L_SUB Term U | λ
Term  → Factor V
V     → L_MUL Factor V | L_DIV Factor V | λ
```
Остальные правила остаются без изменений, так как рекурсии не содержат.

### 3.2. Приведение к нестрогой НФГ
Правила приводятся к виду, где правая часть начинается с терминала или является пустой (`λ`). Для этого нетерминалы в начале правых частей заменяются их развертками. Итоговая грамматика:
```
Program  → StmtList L_EOF
StmtList → ; StmtList | L_ID L_ASSIGN Expr ; StmtList | L_READ L_ID ; StmtList 
         | L_WRITE Expr ; StmtList | L_IF Cond L_THEN StmtList L_ELSE StmtList 
         | L_WHILE Cond L_DO StmtList | λ
Stmt     → L_ID L_ASSIGN Expr | L_READ L_ID | L_WRITE Expr 
         | L_IF Cond L_THEN StmtList L_ELSE StmtList | L_WHILE Cond L_DO StmtList
Expr     → Term U
U        → L_ADD Term U | L_SUB Term U | λ
Term     → Factor V
V        → L_MUL Factor V | L_DIV Factor V | λ
Factor   → ( Expr ) | L_ID ArrayIdx | L_NUM
ArrayIdx → [ Expr ] | λ
Cond     → Expr L_CMP Expr
```
**Результат:** Все правые части начинаются с терминала (`L_ID`, `L_NUM`, `(`, `[`, `+`, `-`, `*`, `/`, `L_IF`, `L_WHILE`, `;` и т.д.) или равны `λ`.

## 4. Семантические действия для генерации ОПС
Генерация обратной польской строки выполняется **параллельно** с синтаксическим разбором. Используется два синхронизированных магазина:
1. **Синтаксический магазин** – хранит терминалы и нетерминалы грамматики.
2. **Магазин семантических действий** – хранит цепочки действий, привязанные к каждому символу правой части правила.

При извлечении символа из синтаксического магазина из второго магазина извлекается и **выполняется** соответствующее семантическое действие.

### 4.1. Система обозначений действий
| Символ | Действие | Описание |
|:---|:---|:---|
| `□` | Пустое | Ничего не делает (проталкивание нетерминала) |
| `ID` | Запись операнда | Заносит в ОПС ссылку на идентификатор из таблицы символов |
| `NUM` | Запись константы | Заносит в ОПС ссылку на константу |
| `+`, `-`, `*`, `/`, `i` | Запись операции | Заносит код операции в ОПС |
| `:=`, `READ`, `WRITE` | Специфическая операция | Генерирует соответствующий код ОПС |
| `JZ`, `JMP`, `LABEL` | Управление | Для генерации переходов в `IF`/`WHILE` |

### 4.2. Таблица LL(1)-анализатора с семантическими действиями (фрагмент)
Ячейки содержат: `Правая часть правила` + `Пробелы` + `Последовательность действий`. Длина цепочки действий строго равна количеству символов в правой части.

| Нетерминал | `L_ID` | `L_NUM` | `L_ADD` | `L_MUL` | `(` | `;` | `L_EOF` |
|:---|:---|:---|:---|:---|:---|:---|:---|
| `Program` | `StmtList L_EOF □□` | | | | | | |
| `StmtList` | `L_ID L_ASSIGN Expr ; StmtList □□□□□` | `L_WRITE Expr ; StmtList □□□□□` | | | | `; StmtList □□` | `λ □` |
| `Expr` | `Term U □□` | `Term U □□` | | | | | |
| `U` | `λ □` | `λ □` | `L_ADD Term U □□+` | `λ □` | `λ □` | `λ □` | `λ □` |
| `Term` | `Factor V □□` | `Factor V □□` | `λ □` | | | `λ □` | `λ □` |
| `V` | `λ □` | `λ □` | `λ □` | `L_MUL Factor V □□*` | `λ □` | `λ □` | `λ □` |
| `Factor` | `L_ID ArrayIdx ID□` | `L_NUM NUM` | | | `( Expr ) □□□` | | |
| `ArrayIdx` | | | | | | `λ □` | `[ Expr ] □□□` |

*Реализация:* Таблицы `LL1_TABLE[нетерминал][терминал]` и `ACTION_TABLE[нетерминал][терминал]` загружаются из внешних структур/файлов.

## 5. Список операций ОПС
Перечень всех операций, которые может сгенерировать парсер. Арность определяет количество операндов, извлекаемых из стека интерпретатора.

| Код операции | Название | Арность | Описание выполнения |
|:---|:---|:---|:---|
| `+` | Сложение | 2 | `a b +` → `a + b`, результат в стек |
| `-` | Вычитание | 2 | `a b -` → `a - b` |
| `*` | Умножение | 2 | `a b *` → `a * b` |
| `/` | Деление | 2 | `a b /` → `a / b` |
| `i` | Индексация 1D | 2 | `arr idx i` → вычисление адреса `arr[idx]`, ссылка в стек |
| `:=` | Присваивание | 2 | `addr val :=` → запись `val` по адресу `addr`, в стек ничего не кладётся |
| `<`, `>`, `==`, `<=`, `>=`, `!=` | Сравнение | 2 | Возвращают `1` (true) или `0` (false) |
| `READ` | Ввод | 1 | `var READ` → чтение значения в переменную `var` |
| `WRITE` | Вывод | 1 | `val WRITE` → вывод значения на экран |
| `JZ addr` | Переход, если 0 | 1 | Извлекает условие. Если `0`, переходит на `addr` |
| `JMP addr` | Безусловный переход | 0 | Переход на метку `addr` |

*Примечание:* Операции управления (`JZ`, `JMP`) генерируются при разборе `IF`/`WHILE`. Адреса переходов заполняются в два прохода или через временный стек меток.

## 6. Формат ОПС
Промежуточный код представляется как линейный массив структур. Каждый элемент содержит тип и значение/ссылку.

### 6.1. Структура элемента ОПС
```c
typedef enum {
    OPS_CONST = 0,    // Константа
    OPS_VAR = 1,      // Простая переменная
    OPS_ARRAY = 2,    // Массив (паспорт/описатель)
    OPS_OP = 3,       // Операция
    OPS_ADDR = 4      // Адрес перехода (метка)
} OPS_Type;

struct OPS_Element {
    OPS_Type type;    // Тип элемента (0..4)
    union {
        int  ref_idx; // Индекс в таблице символов/констант
        int  op_code; // Код операции из раздела 5
        int  addr;    // Смещение в массиве ОПС для переходов
    } data;
};
```

### 6.2. Таблицы, используемые парсером
Парсер формирует ОПС, одновременно регистрируя идентификаторы в таблицах:
| Таблица | Назначение | Содержимое |
|:---|:---|:---|
| `VarTable` | Скалярные переменные | Имя, тип, текущее значение |
| `ConstTable` | Числовые литералы | Значение константы |
| `ArrayTable` | Массивы | Имя, размерность, границы, ссылка на область памяти |

### 6.3. Пример генерации ОПС
**Входная цепочка:** `M[k] := a * b + c`  
**Сгенерированная ОПС (последовательность `OPS_Element`):**
```
(OPS_ARRAY, ref_M)  (OPS_VAR, ref_k)  (OPS_OP, i)
(OPS_VAR, ref_a)    (OPS_VAR, ref_b)  (OPS_OP, *)
(OPS_VAR, ref_c)    (OPS_OP, +)       (OPS_OP, :=)
```
**Интерпретация:**
1. `ref_M`, `ref_k` → в стек. `i` → вычисляет адрес `M[k]`, кладёт ссылку в стек.
2. `ref_a`, `ref_b` → в стек. `*` → умножает, кладёт результат.
3. `ref_c` → в стек. `+` → складывает с предыдущим результатом.
4. `:=` → записывает итоговое значение по адресу `M[k]`. Стек очищается.
